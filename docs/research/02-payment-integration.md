# 리서치 02. 결제 연동 (PG · VAN · 수수료 · 현금영수증)

> 조사 시점: 2026-07. 수수료율·정책은 반기/수시로 변동. 계약 전 반드시 재확인 필요.

## 1. 기본 구조 이해: PG vs VAN

우리 시스템은 **후불 대면 결제(카운터)**와 **선불 비대면 결제(QR 주문)**를 모두 다루므로, 두 체계를 구분해야 합니다.

| 구분 | VAN (대면/오프라인) | PG (비대면/온라인) |
|------|--------------------|--------------------|
| 역할 | 카드 단말 ↔ 카드사 승인 중계 | 온라인 결제창 + 결제수단 통합 대행 |
| 가맹 구조 | 가게가 **카드사에 직접 가맹** | 가게가 **PG에 가맹** (PG가 카드사와 계약) |
| 가맹점 수수료 | 카드사 수수료만 (우대 0.4~1.45%) | PG 수수료 (일반 3.2~3.4%, 우대 시 인하) |
| 정산 | 카드사가 직접 정산 (빠름) | PG 경유 정산 (D+2~7 일반적) |
| VAN/PG 비용 부담 | VAN 수수료는 카드사가 부담 | PG 수수료에 포함 |

참고: [토스페이먼츠 — PG와 VAN 개념](https://www.tosspayments.com/blog/articles/semo-16), [청구스 — PG vs VAN 차이](https://www.chungoose.kr/blog/pg-vs-van-%EC%B4%9D%EC%A0%95%EB%A6%AC-%EC%B9%B4%EB%93%9C-%EC%88%98%EC%88%98%EB%A3%8C-%EC%A4%84%EC%9D%B4%EB%8A%94-%EB%B2%95%EA%B9%8C%EC%A7%80)

### 핵심 시사점

- **같은 카드 결제라도 QR 선불(온라인 PG 경유)은 카운터 결제(VAN)보다 가게 부담 수수료가 높고 정산이 느림**
- 우리 기획의 "후불 기본, 선불 옵션" 방침은 수수료 관점에서도 합리적 — 선불 모드 안내 시 사장에게 이 차이를 명시해야 함
- 가게 입장 최적: 매장 내 결제는 최대한 VAN 단말로, 온라인 선불은 필요한 가게만 선택

## 2. 오프라인 카드 결제 (VAN)

### 주요 VAN사

나이스정보통신, 한국정보통신(KICC), KSNET, 스마트로, KIS정보통신 등이 상위권 (점유율 순위는 나이스·KICC가 선두 경쟁).

참고: [NICE정보통신](https://www.nicevan.co.kr), [KICC](https://www.kicc.co.kr/), [KIS정보통신](https://www.kisvan.co.kr/)

### 연동 방식 (개발 관점)

- POS 소프트웨어는 **VAN사의 승인 에이전트/모듈**을 통해 카드 단말과 통신 (VAN사별 연동 규격 상이)
- 카드 단말기는 **여신금융협회 인증 IC 단말기만 사용 가능** — 미인증 단말 설치 시 VAN사·가맹점에 5천만원 이하 과징금
- POS 단말 보안표준 준수 필요: 카드번호 암호화/마스킹, POS에 카드정보 비보관 설계 권장
- 참고: [여신금융협회 단말기 등록](https://www.crefia.or.kr/portal/store/cardTerminal/cardTerminalList.xx), [보안뉴스 — POS 단말 보안표준](https://m.boannews.com/html/detail.html?idx=47703&kind=3)

### 카드 가맹점 수수료 (2026년 상반기, 우대수수료)

여신전문금융업법에 따라 연매출 구간별 우대수수료가 **반기마다 자동 적용** (전체 가맹점의 95.7%가 우대 대상):

| 연매출 구간 | 신용카드 | 체크카드 |
|------------|----------|----------|
| 3억원 이하 (영세) | 0.4% | 0.15% |
| 3억~5억원 | 1.0% | — |
| 5억~10억원 | 1.15% | — |
| 10억~30억원 | 1.45% | — |

참고: [금융위원회 — 2026년 상반기 영세·중소가맹점 선정](https://www.fsc.go.kr/po010101/86274), [정책브리핑](https://www.korea.kr/news/policyNewsView.do?newsId=148953893)

### SaaS 관점 전략

| 선택지 | 내용 | 평가 |
|--------|------|------|
| A. VAN 직접 연동 | 1~2개 VAN사와 연동 계약, 승인 모듈 통합 | 정석. 개발·계약 비용 크지만 독립적 |
| B. 토스플레이스 연동 | 토스프론트 단말 + 공개 연동 가이드(docs.tossplace.com) 활용 | 초기 개발비 최소. 단말 26만원/대. 플랫폼 종속 |
| C. 결제 미연동 (수동) | POS는 금액만 표시, 결제는 기존 단말로 별도 진행 → 결과만 수기 입력 | MVP 최소안. 소규모 POS들이 실제로 쓰는 방식 |

**권장 로드맵**: MVP는 C(수동 기록) → Phase 2에서 B(토스플레이스) 또는 A(VAN 1개사) 착수. C는 개발 없이 모든 매장의 기존 단말과 "호환"되는 장점이 있어 베타 단계에 유효.

## 3. 온라인 결제 PG (QR 선불 모드용)

### 주요 PG사 비교

상위 4사(KG이니시스, NHN KCP, 토스페이먼츠, 나이스페이먼츠)가 시장의 65~70% 점유.

| PG | 수수료(일반) | 가입비 | 특징 |
|----|--------------|--------|------|
| **토스페이먼츠** | 카드 ~3.3-3.4% | 조사 시점 무료 정책 있음(연 관리비 사례 11만원) | **개발자 경험 최상** (문서/SDK), 신생 서비스 선호도 1위 |
| **KG이니시스** | 2.1~3.3% | 20만원 (조건부 면제) | 최다 가맹점, 전통적 안정성 |
| **NHN KCP** | 2.1~3.3% | 20만원 (조건부 면제) | 해외카드/글로벌 강점, 높은 결제 성공률 |
| **나이스페이먼츠** | 해외카드 3.8% 등 | 20만원 수준 | 휴대폰결제 등 수단 다양 |
| **포트원(구 아임포트)** | PG 수수료 + 포트원 요금 | — | **PG가 아닌 연동 허브** — 복수 PG를 단일 API로, PG 교체 자유 |

- 정산주기: 카드 기준 D+3~7 (영업일)이 일반적
- 온라인도 영세·중소 우대수수료 반기 자동 적용 (PG 하위가맹점 193.8만개 대상)

참고: [포트원 PG 비교 블로그](https://blog.portone.io/pgcompare/), [토스페이먼츠 수수료](https://www.tosspayments.com/about/fee), [가맹점숲 PG 수수료](https://bizimshop.co.kr/pg)

### 멀티테넌트 SaaS 특유의 쟁점 (중요)

일반 쇼핑몰과 달리, 우리는 **여러 가게의 결제를 대신 연동해주는 플랫폼**입니다. 두 가지 구조가 가능합니다:

| 구조 | 설명 | 이슈 |
|------|------|------|
| **가게별 개별 가맹** | 각 가게가 PG에 직접 가입, 우리는 가게별 API 키로 연동 | 정산이 가게로 직접 → 깔끔. 가입 절차를 SaaS가 안내/대행해야 함 |
| **플랫폼 대표 가맹 + 하위몰(서브몰)** | 우리가 대표 가맹점, 가게는 하위몰로 등록, 정산 분배 | 정산 대금이 플랫폼을 거치면 **전자금융업(PG업) 등록 이슈** 발생 가능 → 법적 검토 필수 |

- PG사들의 "지급대행/파트너정산" 상품(토스페이먼츠 지급대행, 포트원 파트너정산 등)이 이 문제를 해결하는 용도 — Phase 2 전 상세 검토 필요
- **초기 권장**: 가게별 개별 가맹 (법적 리스크 없음, 구현 단순). 가입 절차 가이드를 SaaS 온보딩에 포함

## 4. 간편결제 (오프라인 매장)

- **카카오페이**: 오프라인 파트너 가맹(partner.kakaopay.com) → 매장 QR 키트 또는 바코드 스캔(단말 연동). 제로페이 연동으로 가맹점 커버리지 확장 중
- **네이버페이**: 제로페이 QR 연동 방식 지원
- **제로페이**: 소상공인 수수료 0%대, QR 키트 신청 방식 — 시스템 연동 없이도 도입 가능
- 실무 포인트: **최신 VAN 카드 단말 다수가 간편결제 바코드 스캔을 함께 지원** → 단말/VAN 선정 시 간편결제 지원 범위를 함께 확인하면 별도 연동 불필요

참고: [카카오페이 오프라인 파트너](https://partner.kakaopay.com/partner/offline/introduction), [전자신문 — 카카오페이·제로페이 연동](https://www.etnews.com/20240417000141), [제로페이 가맹점](https://www.zeropay.or.kr/UI_HP_004_01_02.act)

## 5. 현금영수증 / 세금계산서

### 현금영수증

- **오프라인(카운터 현금)**: VAN 카드 단말에서 현금영수증 발급 가능 (단말 연동 시 자동 해결)
- **시스템 자동 발급(온라인/POS 통합)**: 국세청 직접 연동 대신 **중계 API 사업자**(팝빌, 링크허브/바로빌 등) 이용이 표준 — 발행 익일 국세청 자동 전송, 취소 발행/대량 신고/Webhook 지원, 건당 과금
- MVP에서는 VAN 단말 발급으로 충분, 매출 리포트 통합 시점에 API 연동 검토

### 세금계산서

- 법인/사업자 고객 대상 — 팝빌 등 동일 사업자의 전자세금계산서 API로 처리 가능
- 음식점 특성상 빈도 낮음 → 후순위

참고: [팝빌 현금영수증 API](https://www.popbill.com/Content/Link/Cash/API), [팝빌 세금계산서 API](https://www.popbill.com/Taxinvoice/API), [링크허브 가이드](http://blog.linkhub.co.kr/2111/)

## 6. 종합 권장안 (로드맵 매핑)

| 시기 | 결제 기능 | 방식 |
|------|-----------|------|
| **MVP (Phase 1)** | 결제 금액 표시 + 수동 결제 기록 | 기존 단말 그대로, POS는 기록만 (연동 없음) |
| **Phase 2** | 카드 단말 연동 | 토스플레이스 연동 vs VAN 1개사 직접 연동 결정 |
| **Phase 2** | QR 선불 결제 | PG 1개사(토스페이먼츠 우선 검토) 가게별 개별 가맹 |
| **Phase 3** | 현금영수증 자동화 | 팝빌 등 API 연동 |
| **Phase 3+** | 멀티 PG / 지급대행 | 포트원 or PG 지급대행 상품, 전자금융업 법적 검토 포함 |

### 남는 결정 사항 (상의 필요)

1. MVP에서 "수동 결제 기록"으로 시작하는 방안에 동의하는지
2. 카드 단말 연동 1차 파트너: 토스플레이스 vs 전통 VAN사
3. QR 선불용 PG: 토스페이먼츠(개발 편의) vs 이니시스/KCP(수수료·안정성)
4. 가게별 개별 가맹 방식으로 확정할지 (플랫폼 대표가맹은 법적 검토 후 재론)
