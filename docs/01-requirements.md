## 2. 비기능 요구사항 (Non-functional Requirements)

### 2.1 확장성 (Scalability)
- **멀티테넌트**: 한 시스템에서 수백~수천 가게를 수용할 수 있어야 함
- 한 가게 내에서 피크 타임(점심·저녁) 동시 주문 처리 가능
- 테넌트별 데이터 격리

### 2.2 보안 (Security)
- 테넌트 간 데이터 접근 차단
- 역할 기반 접근 제어 (RBAC)
- 결제 정보 비저장(PG사 위임), 고객 개인정보 암호화 저장
- 접속 로그 및 감사 로그

### 2.3 가용성 (Availability)
- 영업 시간 중 다운타임 최소화
- QR 주문·POS는 가게 영업에 직접 영향 → 고가용성 필요

### 2.4 성능 (Performance)
- 주문 접수·조회는 1초 이내 응답
- KDS 주문 표시는 실시간(지연 2초 이내)

### 2.5 사용성 (Usability)
- 직원이 별도 교육 없이도 주요 기능을 사용 가능해야 함
- 터치 스크린 POS 환경 대응
- 한국어 UI

### 2.6 호환성
- 웹: 최신 크롬/사파리/엣지 지원
- 모바일: Android / iOS
- 프린터: 표준 영수증 프린터(ESC/POS 등) 지원 — 상세 TBD

## 3. 제약사항 (Constraints)

- 한국 시장 대상(결제·예약·배달 외부 연동은 한국 서비스 위주)
- 개인정보보호법, 전자금융거래법 준수
- 후순위 기능은 MVP에서 제외
