# FR-02. QR 주문

## 목적
고객이 테이블의 QR코드를 스마트폰으로 스캔해, 직접 메뉴를 보고 주문하는 비대면/셀프 주문 기능. 일본에서 보편화된 방식.

## 운영 방식
- **기본**: QR 스캔 → 웹 메뉴 → **주문까지만** (결제는 나중에 카운터에서)
- **선택 옵션**: 특정 고객/모드에서는 결제까지 가능 (선불 모드)
- 가게 설정에서 토글

## 사용자 시나리오
1. 직원이 고객 착석 시 테이블 오픈 → 세션 QR 발급 (단말기 표시 or 영수증 출력)
2. 손님이 세션 QR 스캔 → 해당 테이블 전용 웹 메뉴 페이지 열림
3. 메뉴 둘러보기(사진, 설명, 옵션, 가격)
4. 장바구니에 담기 → 주문 전송
5. 주문이 POS·KDS에 실시간 표시
6. (선불 모드) 결제까지 진행 → 결제 완료 화면
7. (후불 모드) 주문만 완료 → 식사 후 카운터 결제

## 상세 기능
- 세션별 QR 코드 동적 생성 (세션 토큰 포함)
- QR 스캔 시 세션 토큰으로 테이블·주문 권한 자동 식별 → 로그인 불필요
- 카테고리/사진 중심 메뉴 UI
- 옵션 선택, 수량 조절
- 장바구니, 주문 요청사항 메모
- 기존 주문 내역 확인(같은 테이블, 같은 세션)
- 직원 호출 버튼
- 주문 완료 후 POS/KDS에 즉시 반영
- (선불 모드) 간편결제 연동

## QR 제공 방식

QR에 세션 토큰이 포함되어, **QR 자체가 주문 권한**입니다.
정적 URL 스티커 방식은 외부 접근/몰래 주문 등 보안 문제가 있으므로, **세션별 동적 QR**을 사용합니다.
가게 설정에서 A/B 방식 선택 가능.

### 방식 A: 테이블 단말기 디지털 QR
- 테이블에 태블릿 또는 e-ink 디스플레이 설치
- 직원이 테이블 오픈 시 → 세션 생성 → 디스플레이에 세션 QR 자동 표시
- 결제 완료 시 → QR 자동 갱신 (이전 QR 즉시 무효)
- 직원 추가 작업 없음
- 장비 비용 발생 (테이블당 디스플레이)

### 방식 B: 세션 QR 영수증 출력
- 직원이 고객 착석 시 POS에서 세션 생성 → 세션 QR이 포함된 소형 영수증 출력
- 고객에게 전달 → 고객이 스캔하여 주문
- 결제 후 세션 토큰 무효화 (영수증은 회수하거나 자연 폐기)
- 기존 영수증/주방 프린터 활용 가능
- 직원이 매 착석 시 출력/전달 필요

## QR 세션 관리

### 세션 라이프사이클

| 단계 | 트리거 | 동작 |
|------|--------|------|
| **생성** | 직원이 테이블 오픈 (착석 시) | 세션 생성 + 세션 QR 발급 (단말기 표시 or 영수증 출력) |
| **합류** | 일행이 같은 QR 스캔 | 같은 세션에 합류 (추가 주문 가능) |
| **정상 종료** | 결제 완료 | 세션 토큰 무효화 + 테이블 상태 변경 |
| **미수금 종료** | 먹튀/무단 이탈 | 직원이 미수금 처리 + 세션 강제 종료 |
| **수동 종료** | 직원 판단 | POS에서 세션 닫기 (오류/이상 상황) |

### 세션 토큰과 주문 권한
- QR URL에 세션 토큰 포함 (예: `/order/{store_id}/{table_id}?session={token}`)
- **모든 주문 API 호출 시 세션 토큰 서버 검증** → 유효하지 않으면 주문 차단
- QR을 스캔한 사람만 유효한 세션 토큰을 보유 → 외부 접근 원천 차단
- 같은 세션 내 주문은 모두 같은 테이블 주문으로 묶임

### 보안
- **외부 접근 차단**: QR에 세션 토큰이 포함되어 있으므로, QR을 모르면 주문 불가. 정적 URL을 알아도 세션 토큰 없이는 주문 페이지 진입 불가
- **결제 후 재접근 방지**: 세션 토큰 무효화 → 같은 QR을 다시 스캔해도 주문 불가
  - 방식 A: 디스플레이에 새 세션 QR이 자동 표시되므로 이전 QR은 자동 무효
  - 방식 B: 영수증의 QR은 토큰이 서버에서 무효화되어 사용 불가
- **몰래 주문 방지**: QR이 세션별로 고유하므로, QR을 직접 스캔한 사람만 주문 가능
  - 단, QR을 사진 촬영해 외부에 공유하면 해당 세션으로 주문 가능 → 이는 고객 본인 관리 영역
- **브라우저 히스토리/뒤로가기**: 세션 토큰이 URL에 포함되어 있으나, 서버에서 무효화된 토큰은 검증 실패 → 주문 차단

### 세션 만료 정책
- **주문이 있는 세션**: 자동 만료 금지 — 결제 또는 직원 수동 종료만 가능
- **주문 없는 세션**: 영업 종료 시 미주문 세션 일괄 정리가 가장 안전
- **영업 마감 시**: 미종료 세션 목록 표시 → 직원 확인 후 일괄 정리

### 먹튀(무단 이탈) 처리
- 직원이 POS에서 해당 테이블을 **미수금 처리**로 세션 종료
- 주문 내역·금액은 보존, 결제 상태만 **"미수금"**으로 별도 기록
- 미수금 사유 메모 입력 (먹튀, 분쟁 등)
- 미수금 내역은 별도 관리 화면에서 조회 (일별/월별)
- 나중에 회수 시 미수금 → 결제 완료로 전환 가능
- 통계에서 미수금 금액은 **실매출과 구분**하여 집계

## 화면/흐름 스케치
- **메뉴 리스트**: 상단 카테고리 탭, 메뉴 카드(사진·이름·가격)
- **메뉴 상세**: 옵션 선택, 수량, 장바구니 담기
- **장바구니**: 주문 리스트, 메모, 주문하기 버튼
- **주문 확인**: 주문 완료 안내, 현재 주문 상태 표시

## 데이터 입출력
- 입력: 세션 QR 토큰, 메뉴/옵션/수량
- 출력: 주문 레코드(Order with channel=QR), KDS/POS 알림

## 다른 기능과의 연동
- **테이블 관리** (FR-04): 테이블 오픈/세션 QR 발급
- **메뉴 관리** (FR-03): 고객 노출용 메뉴 데이터
- **주문/POS** (FR-01): 주문 레코드 통합
- **결제** (FR-09): 선불 모드에서 간편결제
- **주방 KDS** (FR-08): 주문 알림
