# FR-02. QR 주문

## 목적
고객이 테이블의 QR코드를 스마트폰으로 스캔해, 직접 메뉴를 보고 주문하는 비대면/셀프 주문 기능. 일본에서 보편화된 방식.

## 운영 방식
- **기본**: QR 스캔 → 웹 메뉴 → **주문까지만** (결제는 나중에 카운터에서)
- **선택 옵션**: 특정 고객/모드에서는 결제까지 가능 (선불 모드)
- 가게 설정에서 토글

## 사용자 시나리오
1. 손님이 테이블 QR 스캔 → 해당 테이블 전용 웹 메뉴 페이지 열림
2. 메뉴 둘러보기(사진, 설명, 옵션, 가격)
3. 장바구니에 담기 → 주문 전송
4. 주문이 POS·KDS에 실시간 표시
5. (선불 모드) 결제까지 진행 → 결제 완료 화면
6. (후불 모드) 주문만 완료 → 식사 후 카운터 결제

## 상세 기능
- 테이블별 고유 QR 코드 생성/인쇄
- QR 스캔 시 해당 테이블 자동 식별 → 로그인 불필요
- 카테고리/사진 중심 메뉴 UI
- 옵션 선택, 수량 조절
- 장바구니, 주문 요청사항 메모
- 기존 주문 내역 확인(같은 테이블, 같은 세션)
- 직원 호출 버튼
- 주문 완료 후 POS/KDS에 즉시 반영
- (선불 모드) 간편결제 연동

## QR 세션 관리

### QR 코드 구조
- 테이블에 부착된 QR은 **정적 URL** (예: `/order/{store_id}/{table_id}`)
- QR 스티커를 매번 교체할 필요 없음 — **세션 토큰**이 동적으로 관리됨
- QR 코드 자체는 "이 테이블의 주문 페이지 입구"일 뿐, 권한을 부여하지 않음

### 세션 라이프사이클

| 단계 | 트리거 | 동작 |
|------|--------|------|
| **생성** | 고객이 QR 스캔 + 활성 세션 없음 | 새 세션 생성 + 세션 토큰 발급 + 테이블 "이용중" |
| **합류** | 같은 테이블 QR 재스캔 | 활성 세션이 이미 있으면 → 기존 세션에 합류 |
| **정상 종료** | 결제 완료 | 세션 토큰 무효화 + 테이블 상태 변경 |
| **미수금 종료** | 먹튀/무단 이탈 | 직원이 미수금 처리 + 세션 강제 종료 |
| **수동 종료** | 직원 판단 | POS에서 세션 닫기 (오류/이상 상황) |

### 세션 토큰과 주문 권한
- 세션 생성 시 고객 브라우저에 **세션 토큰** 저장 (쿠키 or 로컬스토리지)
- **모든 주문 API 호출 시 세션 토큰 서버 검증** → 유효하지 않으면 주문 차단
- 세션 토큰이 없거나 만료된 상태로 URL에 접근하면 → **"QR을 스캔해주세요"** 안내 페이지 표시
- 같은 세션 내 주문은 모두 같은 테이블 주문으로 묶임

### 세션 만료 정책
- **주문이 있는 세션**: 자동 만료 금지 — 결제 또는 직원 수동 종료만 가능
- **주문 없는 세션(스캔만 하고 주문 안 함)**: 단순 타임아웃은 위험 (고객이 메뉴를 오래 고를 수 있음)
  - 영업 종료 시 미주문 세션 일괄 정리가 가장 안전
  - 또는 매우 긴 유휴 시간(예: 3시간 이상 무활동) 후 자동 만료 + 테이블 상태 복원
- **영업 마감 시**: 미종료 세션 목록 표시 → 직원 확인 후 일괄 정리

### 결제 후 재접근 방지
- 결제 완료 시 서버에서 **세션 토큰 즉시 무효화**
- 클라이언트: 결제 완료 화면으로 리다이렉트 + 브라우저의 세션 데이터 삭제
- 이후 같은 URL 접근 시 (브라우저 히스토리/뒤로가기 포함):
  - 세션 토큰 없음 → "QR을 스캔해주세요" 페이지
  - 만료된 세션 토큰 → 서버 검증 실패 → "QR을 스캔해주세요" 페이지
- **핵심**: 정적 URL 자체는 주문 권한이 아님. 유효한 세션 토큰이 있어야만 주문 가능

### 비정상 접근 방지
- **QR 사진 저장 후 원격 접근 시도**:
  - 정적 URL이므로 페이지 접근 자체는 가능
  - 그러나 테이블이 "이용중"이면 → 기존 세션에 합류 (의도하지 않은 주문 혼입 위험)
  - 테이블이 "빈자리"면 → 새 세션 생성 가능 (원격에서 악의적 주문 가능)
- **대책 (가게 설정으로 선택)**:
  - **기본**: 새 세션 생성 시 홀 직원에게 알림 → 실제 착석 확인
  - **강화**: 세션 생성 시 직원 확인(승인) 필수 → 확인 전까지 주문 차단
  - QR 스캔 시 직원 확인이 부담되는 가게는 기본 모드 사용

### 먹튀(무단 이탈) 처리
- 직원이 POS에서 해당 테이블을 **미수금 처리**로 세션 종료
- 주문 내역·금액은 보존, 결제 상태만 **"미수금"**으로 별도 기록
- 미수금 사유 메모 입력 (먹튀, 분쟁 등)
- 미수금 내역은 별도 관리 화면에서 조회 (일별/월별)
- 나중에 회수 시 미수금 → 결제 완료로 전환 가능
- 통계에서 미수금 금액은 **실매출과 구분**하여 집계

## 화면/흐름 스케치
- **메뉴 리스트**: 상단 카테고리 탭, 메뉴 카드(사진·이름·가격)
- **메뉴 상세**: 옵션 선택, 수량, 장바구니 담기
- **장바구니**: 주문 리스트, 메모, 주문하기 버튼
- **주문 확인**: 주문 완료 안내, 현재 주문 상태 표시

## 데이터 입출력
- 입력: 테이블 QR 토큰, 메뉴/옵션/수량
- 출력: 주문 레코드(Order with channel=QR), KDS/POS 알림

## 다른 기능과의 연동
- **테이블 관리** (FR-04): 테이블별 QR 토큰 발급/관리
- **메뉴 관리** (FR-03): 고객 노출용 메뉴 데이터
- **주문/POS** (FR-01): 주문 레코드 통합
- **결제** (FR-09): 선불 모드에서 간편결제
- **주방 KDS** (FR-08): 주문 알림
