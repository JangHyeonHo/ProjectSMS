# 06. 단계별 개발 로드맵

기간은 명시하지 않고 **단계별 목표**로 구성합니다. 각 Phase 완료 시 사용자 리뷰를 받고 다음 단계로 진행합니다.

---

## Phase 0 — 기획 확정 & 기술 스택 결정

**목표**: 본 문서 세트 확정 및 기반 결정

- [ ] 모든 `docs/` 문서 리뷰·승인
- [ ] `07-open-questions.md`의 핵심 미정 사항 결정
- [ ] 기술 스택 선정(프론트/백/DB/인프라)
- [ ] 프로젝트 저장소 구조 초안
- [ ] CI/CD 기본 파이프라인

**산출물**: 확정된 기획서 + 기술 스택 결정서 + 빈 프로젝트 스켈레톤

---

## Phase 1 — MVP: 기본 POS & 메뉴 & 테이블 & 결제

**목표**: 단일 가게가 실제 영업에 쓸 수 있는 최소 POS 완성

- 멀티테넌트 기반 구조(Tenant/Store/User)
- 로그인, 권한(사장/직원 2단계)
- 메뉴 관리(기본 + 옵션)
- 테이블 관리(기본 배치도, 상태)
- 주문 접수/수정/취소
- 결제: 현금 + 카드(수동) + 영수증 출력
- 주방 프린터 출력
- 매출 조회(일별)

**제외**: KDS, QR 주문, 재고, 직원관리, 예약, 고객앱

---

## Phase 2 — QR 주문 & KDS & 재고 기본

**목표**: 비대면 주문 + 주방 디지털화 + 재고 기초

- QR 주문 웹(고객용 메뉴 → 주문)
- 테이블별 QR 토큰 발급
- KDS 화면(신규/조리중/완료)
- 재고 기본(식자재 등록, 입출고, 수동 차감)
- 레시피 등록(메뉴-식자재 매핑)
- 메뉴 품절/신메뉴/시간대 노출

---

## Phase 3 — 직원 관리 & 예약

**목표**: 인사/스케줄 + 전방위 예약

- 직원 등록 + 세부 권한
- 스케줄 캘린더
- 출퇴근 기록 + 근무시간 집계
- 예약: 수동 등록 + 고객 온라인 예약
- 예약 알림(SMS)
- 재고 차감 고도화: 개수 품목(병/캔) 즉시 자동 차감 + 일반 식자재 마감 수동 차감 + 레시피 기반 예상량 참고 표시

---

## Phase 4 — 통계 대시보드 & 고객앱

**목표**: 사장 인사이트 + 단골 관리

- 상세 분석 대시보드(매출/메뉴/시간대/고객/테이블)
- 리포트 다운로드(PDF/엑셀)
- 고객 프로필 관리
- 포인트 적립/사용
- 쿠폰 발행/사용
- 마케팅 알림(푸시/SMS/알림톡)
- 수신 동의 관리

---

## Phase 5 — 외부 연동 확장

**목표**: 외부 서비스 연동으로 실사용성 강화

- 간편결제 PG 연동(카카오페이/네이버페이 등)
- 네이버 예약 API 연동
- 카카오 예약 연동(가능 시)
- 현금영수증 / 세금계산서 발급
- 배달앱 연동(배민/쿠팡이츠 등 — 후순위)

---

## Phase 6+ — 장기 확장 (아이디어)

- 다점포 본사-가맹점 구조
- AI 기반 수요 예측 / 발주 추천
- 회계·세무 프로그램 연동
- 자체 배달 시스템
- 해외 진출(다국어)

---

## 리스크 관리

- **결제/프린터 하드웨어 연동**이 일정 불확실성 큼 → Phase 1에서 prototype 확보
- **외부 API 승인 절차**(네이버/카카오) 리드타임 고려 → Phase 5 전 미리 신청
- **멀티테넌트 격리 실수**는 치명적 → 초기 설계에서 자동화된 테넌트 필터 강제
